# 文献速读卡生成器

## 目标

围绕用户给定主题，找到一组可核验的代表性文献，提取能快速判断论文价值的证据，并生成简洁、可引用、能说明因果边界的中文速读卡。需要网页展示时，生成一个可离线打开的 HTML 卡库。

## 工作流

### 1. 明确范围

- 读取用户的主题、对象、时间范围、学科和文献数量；缺失时采用可逆假设并显式说明。
- 默认先做约 10 篇：优先纳入系统综述/元分析、纵向研究、随机对照或实验研究，再补充高相关横断面研究和理论/测量研究。
- 将宽主题拆成 3–5 个检索方向，例如：核心变量、结果变量、作用机制、干预证据、局限与边界。

### 2. 检索与核验

- 使用网页检索；技术、学术和最新信息优先查看原始论文、期刊页面、PubMed、PMC、DOI 页面或出版社页面。
- 同时使用中文和英文关键词。每篇文献至少记录：作者、年份、题名、期刊/会议、DOI 或稳定链接、研究设计、样本/数据、主要变量和关键结果。
- 不把搜索摘要、二手文章或模型记忆当作已核验事实。无法打开全文时，只使用来源中确实可见的信息，并标注“摘要/页面未提供完整细节”。
- 不补写未确认的样本量、效应量、页码、表号或显著性；不把相关写成因果。
- 记录每条关键结论的出处位置：摘要、引言、方法、结果、讨论、表/图编号或 DOI 页面；只有确实核验后才写页码。

### 3. 组织文献组合

- 给每篇文献标注证据类型：综述、元分析、实验/随机对照、纵向、横断面、质性或理论研究。
- 让文献组合覆盖“现象—机制—结果—干预—边界”，避免 10 篇都只是同一种横断面问卷。
- 对高风险偏倚、特殊情境样本、疫情时期数据、单一学校样本和自陈量表单独标记。

### 4. 生成速读卡

每张卡严格使用四个部分，具体字段见 [references/card-schema.md](references/card-schema.md)：

1. 核心结论：最多 3 条，每条尽量带关键数据、方向和变量关系。
2. 研究方法：一句话，包含样本/数据、工具或变量、研究设计和分析方式。
3. 可引用点：写出可以引入用户论文的结论，并注明出处位置；区分“可直接引用的结果”和“需要谨慎转述的讨论”。
4. 局限与注意：说明抽样、测量、设计、外推和因果推断限制。

控制冗余：卡片优先回答“研究发现了什么、怎么发现、我能引用什么、不能推出什么”，不要复述摘要或写成长段综述。专业术语首次出现时用中文短注释，例如“中介效应（解释作用路径）”“调节效应（影响关系强弱）”“横断面设计（同一时间点调查）”。

### 5. 生成 HTML 卡库

- 优先沿用用户现有项目的 HTML/CSS/JS 结构，不擅自引入框架或依赖。
- 数据与页面分离：将文献内容放入数据对象，将渲染、主题、打印和复制引用保留在共享脚本中。
- 文献索引使用真实文件名映射，不假定 `id.html` 一定存在。生成后必须检查每个 `CARD_FILES` 目标文件存在，且每个页面的 `data-card` 与数据 ID 一致。
- 用户提供海报或背景图时，使用相对路径并保留主题切换；文字默认中文，英文标题只在有助于检索或引用时保留，并给出中文含义。
- 桌面端和移动端都要检查：标题换行、卡片高度、背景裁切、按钮可读性、外链可用性和本地 `file://` 打开路径。
- 使用 `scripts/validate_card_library.mjs <library-dir>` 做结构和 JavaScript 语法校验。

### 6. 延续视觉风格

- 默认采用编辑部/电影海报方向：真实背景图、克制的标题层级、细线分隔和少量暖色强调，不使用通用紫色渐变或堆叠式营销卡片。
- 背景图存在时，让背景成为主体；内容面板使用半透明深色层并保留可读对比度，避免完全不透明地遮住画面。
- 默认中文界面；英文题名、期刊名或专业缩写只在检索和引用有价值时保留，并给出中文解释。
- 速读卡保持短：优先数字、变量关系和出处，不把页面写成摘要全文；长内容放入外链或原文位置提示。

## 交付前检查

- 文献数量符合用户要求，题名、作者、年份和 DOI 可追溯。
- 每张卡四段齐全；核心结论不超过 3 条；研究方法为一句话。
- 每条可引用点有出处位置；所有关键数字都能回到来源。
- 局限部分明确写出“能否推因果”。
- HTML 索引的每个链接都能对应真实文件；JavaScript 语法检查通过。
- 向用户区分已核验事实、基于多个来源的归纳和仍需全文确认的内容。
